# Spec 6 — Assessment

*Provides: quiz service (6.1) — the fixed contract parallel lanes build against. Consumes: 2, 3, 4 (syllabus concepts), 5 (SUMMARY docs, completion pipeline). See PLAN.md for status.*

- **6.1 MUST** — Polymorphic `quizzes` + `quiz_attempts` serving all four types (checkpoint / homework / final / refresher) through one service. *Done: four types create rows via one service.*
- **6.2 MUST** — Homework: quiz + suggested reading on lesson completion (rides 5.4.1); result feeds next WK update. *Done: homework attempt visible in WK diff.*
- **6.3 MUST** — Final exam: covers every lesson the syllabus teaches, gates `completed`. *Done: pass flips state; fail records attempt, course stays `active`.*
  - **6.3.1 MUST** — Coverage is per lesson, not per concept. Every lesson in the syllabus is reachable through at least one question; no concept is individually required. A tag resolves to its lesson through `SyllabusConcepts`, which already holds slug → lesson positions. Replaces the rule that every slug in `final_exam_concepts` had to be some question's tag, which could not be satisfied at course size ([T5](../lessons.md)). *Done: an exam whose questions touch all 8 of course 1's lessons passes; one constructed to skip lesson 3 is refused and says which lesson; one that omits 30 individual concepts but touches every lesson passes.*
  - **6.3.2 MUST** — The exam asks two questions per lesson. `QuizLength::exam()` takes the lesson count from the caller, which already loads the syllabus; `homework()` and `refresher()` are untouched. Depth parameters allow 5–10 lessons, so the exam runs 10–20 questions and `pass_mark: 0.7` resolves to 70–75% — no wider than the 70–78% the fixed 8–12 range produced (ledger [D20](../02-design.md) rider 3, amended). The prompt states **both** the computed total and the per-lesson rule — `question_count` is a prompt variable rather than prose, because the model doing the arithmetic itself invites a rejected reply at `top`-tier prices, and because "student picks 1–5 per lesson" (v1.1) is then a different number rather than an edited prompt. *Done: a 5-lesson course generates 10 questions and a 10-lesson course generates 20; the rendered prompt states that same number and the per-lesson rule; the syllabus screen shows the number the exam then asks; the guard holding prompt and schema together fails if any of the three disagree.*
  - **6.3.3 MUST** — A question's `concept_tag` resolves against every concept the lesson sections declare (`SyllabusConcepts::declared()`), not against `final_exam_concepts`. Without this, a question about a real lesson-4 concept outside the declared exam list is stripped of its tag and its lesson counts as uncovered, so 6.3.1 could not be satisfied. *Done: a question tagged with a declared concept outside `final_exam_concepts` keeps its tag and counts toward its lesson; a question tagged with an invented slug still has its tag nulled.*
  - **6.3.4 SHOULD** — The answer sheet: a student's selections are saved as they are made, and grading still happens once, at hand-in. One row per (exam, student, sitting) holding question id → option id, replaced on each save, holding **selections only and no verdicts** — which is what keeps [D20](../02-design.md)'s no-disclosure rule intact. `QuizGrader` remains the sole writer of `quiz_attempts` and `correct` stays `NOT NULL`. The sheet is cleared when the sitting is handed in, so a re-sit opens an empty book. Saving on each selection MUST; debouncing MAY. Ejectable — the exam is sittable without it, and it is the only item in 6.3.* that can be dropped without leaving the course broken. *Done: answer six of sixteen, reload, the six ticks are still there; hand in, reload, the result renders and no draft remains; fail, re-sit, the book opens with nothing ticked; one student's sheet is never visible to another.*
  - **6.3.5 MUST** — A regression guard at realistic size. Every fixture in the suite declares three exam concepts, which is small enough to hide a rule that only binds at course size ([T5](../lessons.md)). *Done: a test builds a syllabus of at least 8 lessons and 40+ declared concepts and asserts an exam generates; deleting 6.3.1's per-lesson rule makes a test fail rather than only production.*
- **6.4 MUST** — Refresher quizzes, subtopic + lesson grain, from WK + SUMMARY docs. *Done: lesson refresher questions traceable to its summary.*
- **6.5 SHOULD** — Module-grain quiz via 3.3 pointer-walk. *Done: 2-subtopic module quiz draws from both WKs.*

## Dogfood repair (2026-09-07)

- **6.6 MUST** — The correct option's position is distributed, not left to the model. No shuffle exists anywhere in `app/` or `resources/js/`: options render in the order the model emitted them and the model chooses `correct_option_id`, and observed checkpoints cluster on A and B. *Done: across 40 generated questions no option position holds the correct answer more than 40% of the time; a test asserts the distribution over a fixed set.*
  - **6.6.1 SHOULD** — Four options become the norm rather than the ceiling. `QuestionSchema::MIN_OPTIONS` is 3, so many questions have no D to choose. *Done: the constants express the intended shape; a D position exists to be chosen.*
